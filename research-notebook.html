01

Conclusion first

Current interpretation · September 2026
  • The original research correctly separated actuation, RT D, and RT A.
  • It did not verify mouse coverage early enough.
  • That allowed a passing keyboard profile and an incorrect sensitivity to appear as one keyboard problem.

How to read these notes

First-time reader

Read the conclusion and variable model first. They define the dependency order before the history introduces older numbers.

New GunZ player

Treat movement names as test examples. You only need one familiar sequence before the input method becomes useful.

Veteran GunZ player

Use the symptom-to-variable logic and checkpoints. The historical server results document my path, not your required destination.

Keyboard enthusiast

Separate switch behavior from game application: actuation, RT D, and RT A describe input events; GunZ movement describes the test context.

02

What changed the method

Real-world typing failure
Observed
  • 0.60 mm caused too many errors during a real interview.
  • The setting did not preserve my normal typing fluency.
Changed
  • Regular keys returned to 1.50 mm to mirror my MCHOSE work keyboard.
  • Rapid Trigger stays off in the untouched typing profile.
Meaning
  • The keyboard must remain dependable for work, writing, and GunZ.
  • The GunZ profile starts from the typing-safe baseline and adds RT only where movement needs it.
Changed question: not “How fast can I make the keyboard?” but “What is the shallowest actuation that preserves my normal typing, and how can Rapid Trigger help where that actuation falls short in GunZ?”
03

Revised variable model

One job per control

View environment

Resolution, aspect ratio, FOV, camera distance, and crosshair define what the same motion looks like. They are controlled conditions, not tuning leftovers.

DPI + sensitivity

DPI is the hardware count density. GunZ sensitivity scales it in the game. Cm/360 records the physical result. Together they determine whether the mouse can cover and place the target.

Actuation

The first ON from the released top. It must remain deliberate and fluent during normal typing before gaming adjustments begin.

RT D · release

The upward distance required before OFF. It is adjusted when later releases repeatedly fail—not simply because an opponent is fast.

RT A · reactivation

The downward distance after reversal before the next ON. It is adjusted when movement is clean but repeatedly behind the pace.

PvP result

The final system check. The movement must stay executable while the verified mouse keeps and places the opponent.

04

Mouse verification protocol

Required before keyboard tuning
What this isolatesMouse coverage and aim distance without keyboard movement.
Why it comes firstA keyboard cannot fix an opponent leaving the usable view.
Passing evidenceTargets stay visible and tracking does not repeat one over- or undershoot direction.
  1. Choose one familiar hardware DPI and disable accidental DPI switching.
  2. Load your real GunZ resolution, aspect ratio, FOV, and camera settings.
  3. Stand still. Track moving players with the mouse only; do not judge keyboard timing yet.
  4. Measure the result in cm/360 with Mouse-Sensitivity.com or a physical 360° test.
  5. Work in 0.1 cm steps. Lower cm/360 is faster; higher cm/360 is slower.
  6. Freeze the first value that repeatedly keeps targets in view without repeated over- or undershoot.

What eDPI can and cannot do

eDPI = DPI × GunZ sensitivity
equivalent GunZ sensitivity = eDPI ÷ new DPI

This transfers a value between DPIs inside the same GunZ input setup. It does not guarantee the same feel across different games, FOV models, acceleration states, clients, or input APIs. Cm/360 is the physical verification.

06

Rapid Trigger protocol

Keyboard movement only
What this isolatesRelease-to-OFF and reactivation-to-ON during repeated movement.
Why it comes hereThe mouse, view, and typing-safe first press are already controlled.
Passing evidenceOne familiar sequence repeats cleanly without one recurring failure.
  • Duplicate the typing-safe base; never overwrite it.
  • Enable Rapid Trigger only on keys that need repeated inputs.
  • Establish an RT D release you can clearly clear and keep it fixed.
  • Start RT A conservatively and lower it one small step only when clean movement repeatedly falls behind.
01First ONFixed actuation from the released top.
02Continue downThe key stays ON toward bottom-out.
03 · RT DRelease to OFFUpward distance required before the key turns OFF.
04ReverseYour finger stops rising and starts pressing again.
05 · RT ANext ONDownward distance after reversal before reactivation.
Diagnostic rule: RT A is the first pacing adjustment. RT D changes only when release clearance is the repeated failure. The labels may differ on other keyboards, so match the direction and event—not just the vendor’s name.
07

Combined PvP validation

Two passes, never two live variables
Pass A · Movement

Does the move stay clean and keep pace?

Freeze DPI, cm/360, view settings, actuation, and RT D. Fight familiar opponents. If the character repeatedly arrives behind even though the sequence is clean, adjust RT A one step.

Pass B · Aim

Can the mouse keep and place the target?

Freeze the passing keyboard. Use a visible center dot if your client has no crosshair. If opponents repeatedly leave the screen or the crosshair lands short/long, adjust cm/360 by 0.1 cm and retest.

  • Run the movement pass first and keep the mouse fixed.
  • Freeze the passing keyboard before the aim pass.
  • Change RT A for repeated movement pacing; change cm/360 for repeated aim direction.
  • Keep the pair unchanged for several sessions before calling it preferred.

09

History retained, not discarded

Earlier results remain evidence

The earlier keyboard work remains useful because it established what each control changes. It is now archived below the final method so readers do not mistake a historical personal checkpoint for the required starting point.

Original 0.20 mm WASD profile
The first method pushed WASD actuation to 0.20 mm and tuned other action keys around it. It produced speed, but required a gaming-specific physical baseline that did not translate cleanly to everyday typing.
1.75 / 0.65 first Rapid Trigger baseline
With 0.20 mm WASD, RT A was lowered from 1.95 to 1.75 mm while RT D stayed at 0.65 mm. This identified a repeatable double-tap pace and clarified that reactivation and release were separate events.
1.55 mm actuation discovery
Using an approximately 3.30 mm calibrated bottom, 3.30 − 1.75 = 1.55 mm became a physical travel reference. It later passed a typing test with Rapid Trigger off. This was a valid personal result, but the newer real-world test now favors 1.50 mm for regular keys.
Server-specific RT A checkpoints
iGunz, FXP GunZ, and FGunZ produced different repeatable personal RT A values while other conditions were held still. Those results document the tuning path; they do not measure or rank server delay.

Glossary in the order it is used

Keyboard language translated into GunZ testing
DPI
The mouse sensor's count density. It is a hardware setting, not a measurement of how the game looks on screen.
cm/360
The physical mouse distance needed to rotate the in-game view one full turn. Lower cm/360 is faster; higher cm/360 is slower.
Actuation
The first ON from the released top. It must remain deliberate and fluent during normal typing before gaming adjustments begin.
RT D · Deactivate
The upward distance required before OFF. It is adjusted when later releases repeatedly fail—not simply because an opponent is fast.
RT A · Activate
The downward distance after reversal before the next ON. It is adjusted when movement is clean but repeatedly behind the pace.
Checkpoint
A complete saved record of the settings and test conditions that passed. It is the rollback point before one value changes.
GunZ movement sequence
A repeatable in-game action such as Flash Step, PPQ, or GDHS. The site uses these as tests; it does not teach the movement itself.
