00 / METHOD
One chain, one variable at a time

What a correct result has to prove.

A passing keyboard test is only one part of a passing input setup. The final result must survive typing, isolated movement, tracking, and real combat without one adjustment hiding a problem in another.

Read from where you are

One method, four useful entry points.

The order does not change by audience. What changes is the context you may need before the same test makes sense.

First-time reader

Start with the order, not the numbers. Each section explains what a setting changes before it asks you to test it.

New GunZ player

This guide does not teach every movement. Learn one sequence you can repeat, then use the method to remove input uncertainty around it.

Veteran GunZ player

Keep the habits that already work. Change a value only when the same symptom repeats, and save checkpoints instead of copying my final numbers.

Keyboard enthusiast

GunZ receives ordinary key ON and OFF states. The millimeter settings change when those states happen; they do not measure skill or server timing.

02 / LOCK
Before touching a value

Stabilize the test environment.

A sensitivity or Rapid Trigger result only means something when the surrounding conditions are recorded and held still.

Record these first

  • GunZ client/server and map
  • Resolution and aspect ratio
  • FOV and camera distance
  • Crosshair and any on-screen dot
  • Mouse DPI, polling rate, Windows pointer settings, and acceleration/raw-input state
  • Keyboard mode, SOCD state, actuation, RT A, and RT D

Resolution changes perception, not hardware DPI

Your mouse DPI is set by the sensor or mouse software. Moving from a 16:9 desktop to a 4:3 or stretched GunZ image can still make horizontal motion look faster, narrower, or unfamiliar because the displayed geometry changed.

Use the aspect ratio you actually play. A desktop icon-pointing drill can help you notice visual mismatch, but treat it as a perception check—not a DPI measurement. Confirm the final result inside GunZ.

Plain terms: FOV means field of view—how much of the game world fits in the view. Camera distance is how far the view sits behind the character. Polling rate is how often the mouse reports. Raw input means the game reads mouse movement without Windows pointer scaling.
03 / MOUSE
Build the aiming base first

Verify DPI and sensitivity before tuning movement.

Start with the DPI you already use every day. The goal is not a fashionable number—it is a stable physical reference you can reproduce.

Why stand still: it removes keyboard movement from the first aiming test. Tracking means following a moving player with the crosshair. Cm/360 is the physical mouse distance needed to turn the view one full rotation.

Mouse protocol

  1. Choose one familiar hardware DPI and disable accidental DPI switching.
  2. Load your real GunZ resolution, aspect ratio, FOV, and camera settings.
  3. Stand still. Track moving players with the mouse only; do not judge keyboard timing yet.
  4. Measure the result in cm/360 with Mouse-Sensitivity.com or a physical 360° test.
  5. Work in 0.1 cm steps. Lower cm/360 is faster; higher cm/360 is slower.
  6. Freeze the first value that repeatedly keeps targets in view without repeated over- or undershoot.

Why use cm/360

A GunZ sensitivity number has no physical meaning by itself. The same +5 change produces a different effective change at 850 DPI than at 1800 DPI. Cm/360 turns the result into a physical distance you can compare deliberately.

eDPI = DPI × in-game sensitivity
new sensitivity = eDPI ÷ new DPI

Use eDPI only inside the same game and input pipeline. It is not a universal cross-game unit because games can use different yaw and FOV behavior.

Why fixed sensitivity steps can mislead: +5 sensitivity at 850 DPI changes eDPI by 4,250. The same +5 at 1,800 DPI changes it by 9,000—more than twice as much. A 0.1 cm/360 target expresses the physical change you actually meant.

04 / TYPE
The everyday baseline

Find an actuation point you can still type on.

Your Hall-effect keyboard is already a gaming peripheral. The useful advantage comes from tuning it without making normal work worse.

Typing terms: WPM is words per minute; accuracy is how much you typed without correction. The passing value is not your fastest score—it is the shallowest actuation that keeps both near your normal range during repeated tests and real writing.

Typing test

  1. Turn Rapid Trigger off and use one fixed actuation value across the regular keys.
  2. Warm up, then run several familiar Monkeytype tests—not one lucky score.
  3. Watch both WPM and mistakes. Keep the shallowest value that preserves your normal fluency.
  4. Retest in real writing: email, chat, editing, and any work where corrections matter.
  5. Save this as the typing baseline before creating the GunZ profile.
Personal observation

0.60 mm failed the real-world test

At 0.60 mm I made too many mistakes during an interview and could not type as fluently as usual. Returning the regular keys to 1.50 mm matched my work keyboard more closely and restored the consistency I needed.

The lesson: a value that feels fast in GunZ can still be wrong for the keyboard as a whole. Actuation must pass normal typing before Rapid Trigger is allowed to compensate for movement.

05 / RAPID TRIGGER
Rapid Trigger has two separate jobs

Confirm the cycle before tuning movement.

Actuation controls the first press from the top. Rapid Trigger Deactivate controls when the released key turns OFF. Rapid Trigger Activate controls how far you press back down after reversal before the next ON.

Input states in plain language: ON means GunZ sees the key as pressed; OFF means GunZ sees it as released. Actuation controls the first ON. RT D creates the later OFF. After your finger reverses direction, RT A creates the next ON.

This is release clearance. Lowering it means less upward lift is needed to turn the key OFF. Change it when the first action works but later releases repeatedly fail, tumble, or stay held. Too low can make the release feel nervous or uneven.

This is reactivation distance after reversal. Lowering it makes the next ON happen sooner. Change it when the movement is already clean but repeatedly cannot keep pace. Too low can outrun your rhythm or create unwanted repeats.

06 / TRAIN
Isolate keyboard execution

Make one familiar movement repeatable by itself.

Training answers one narrow question: can the movement complete cleanly under controlled conditions? It does not prove that aim or opponent coverage is correct.

01

Set up

  • Use one move you already know.
  • Choose level ground and warm up first.
  • Freeze mouse, view, actuation, and RT D.
02

Test

  • Run chains of at least five for about 15 minutes.
  • Count dead dashes, tumbles, held inputs, and unwanted repeats.
  • Ignore one-off mistakes; look for one repeated symptom.
03

Decide

  • Lower RT A one small step only when clean movement is repeatedly behind.
  • Change RT D only when later releases repeatedly fail.
  • Save the first repeatable result before PvP.
Training pass: roughly 90–95% clean execution across a real session, without one repeated failure pattern. This proves keyboard execution only.
07 / FIGHT
The combined test

Validate movement and aim in separate passes.

The keyboard should make movement reliable; the mouse should keep the fight visible and place the shot. Test both in combat, but never change both during the same comparison.

For this method, clean movement means the intended GunZ sequence completes without repeated dead dashes, tumbles, held inputs, or accidental repeats. Aim placement means where the crosshair lands after the mouse follows that movement.
Pass A · Movement

Does the move stay clean and keep pace?

Freeze DPI, cm/360, view settings, actuation, and RT D. Fight familiar opponents. If the character repeatedly arrives behind even though the sequence is clean, adjust RT A one step.

Pass B · Aim

Can the mouse keep and place the target?

Freeze the passing keyboard. Use a visible center dot if your client has no crosshair. If opponents repeatedly leave the screen or the crosshair lands short/long, adjust cm/360 by 0.1 cm and retest.

Combined pass: movement stays executable, the opponent stays within controllable mouse coverage, and the crosshair does not show one repeated directional miss. Keep the pair unchanged before troubleshooting anything else.
08 / DIAGNOSE
Follow the repeated symptom

Change the control that owns the failure.

One miss is noise. A repeated pattern is evidence. Keep every unrelated value fixed, change one control, and return to the last passing checkpoint when the result becomes unclear.

Direction rule: lower cm/360 makes the view faster; higher cm/360 makes it slower. Repeated undershoot or inability to keep up can justify a slightly lower cm/360. Repeated overshoot can justify a slightly higher cm/360.

10 / GLOSSARY
Definitions once, in the order they are used

Translate the setting into the test.

Every entry separates the hardware or guide term from the reason it matters in this method. Colored terms elsewhere open a short version without taking you out of the step.

Keyboard terms

Actuation

What it is: The fixed position measured from the released top where the first downward press reports ON.

Why it matters: It controls the first press; RT A controls a later press after reversal.

Use here: Keep the shallowest value that preserves normal typing fluency.

Rapid Trigger

What it is: Movement-relative behavior that uses travel distance and direction to report OFF and ON again.

Why it matters: A repeated press can register without returning to one fixed reset position.

Use here: Separate release clearance from reactivation pace and test one symptom at a time.

RT D · Deactivate

What it is: The upward distance an active key travels before it reports OFF.

Why it matters: A clean next ON requires the previous press to turn OFF first.

Use here: Change it only when later releases repeatedly fail to clear.

Reversal

What it is: The point where upward release stops and downward pressing begins.

Why it matters: RT A begins measuring the next downstroke from this change of direction.

Use here: Do not treat OFF and reversal as though they must happen at the same position.

RT A · Activate

What it is: The downward distance required after reversal before the next ON.

Why it matters: It changes how much re-press travel is required in a repeated-input cycle.

Use here: Lower it in small steps only when clean movement repeatedly falls behind.

Split Sensitivity

What it is: A keyboard option that assigns separate downstroke and upstroke sensitivity values.

Why it matters: It lets RT A and RT D be tested independently.

Use here: Match each vendor control by direction and event, not only by name.

Continuous Rapid Trigger

What it is: A mode that keeps Rapid Trigger active until the key is fully released.

Why it matters: Changing the mode changes where movement-relative behavior remains available.

Use here: Record its state and keep it fixed during comparisons.

SOCD / Snappy Tappy

What it is: A separate feature that decides how opposing directions are resolved.

Why it matters: It can change directional output without changing RT A or RT D.

Use here: Record it and leave it unchanged while tuning Rapid Trigger.

Total travel and bottom-out

What it is: The full physical key distance and its deepest position.

Why it matters: It sets the travel available for actuation, release, reversal, and re-press.

Use here: Use the Cycle Tester to check travel capacity, not to predict finger rhythm.

Equivalent controls on other keyboards

What it is: Different Hall-effect software may use Trigger, Reset, Press, Release, Activate, or Deactivate.

Why it matters: Matching only a label can reverse the intended adjustment.

Use here: Downward re-press maps to RT A; upward release maps to RT D.

Mouse and guide terms

DPI

What it is: The mouse sensor's count density. It is a hardware setting, not a measurement of how the game looks on screen.

Why it matters: It changes how many counts reach the game's sensitivity calculation.

Use here: Start from the DPI you already use and prevent accidental switching.

cm/360

What it is: The physical mouse distance needed to rotate the in-game view one full turn. Lower cm/360 is faster; higher cm/360 is slower.

Why it matters: It gives sensitivity a physical meaning that can be compared deliberately.

Use here: Adjust by 0.1 cm only after the repeated aim direction is clear.

eDPI

What it is: DPI multiplied by in-game sensitivity.

Why it matters: It transfers an equivalent sensitivity between DPIs inside the same game pipeline.

Use here: Use it for conversion; use cm/360 for physical verification.

Baseline

What it is: A known starting or rollback setting before calibration.

Why it matters: It gives every change a clean comparison.

Use here: Duplicate the base and never overwrite the last passing version.

Checkpoint

What it is: A complete saved record of the settings and test conditions that passed. It is the rollback point before one value changes.

Why it matters: It keeps a worse result from erasing a proven one.

Use here: Save after typing, mouse, training, and combined passes.

Training calibration

What it is: A controlled test of one familiar move on level ground.

Why it matters: It proves keyboard execution without aim, pressure, or opponent positioning.

Use here: Save the first repeatable result before PvP.

PvP validation

What it is: Testing an already-clean movement against real players.

Why it matters: Opponent pace, pressure, position, tracking, and shots are missing from training.

Use here: Run a movement pass and an aim pass without changing both systems together.

Movement undershoot

What it is: The character repeatedly arrives behind the opponent while mouse and view stay fixed.

Why it matters: It separates movement pace from crosshair distance.

Use here: Investigate RT A only after movement is clean.

Aim undershoot

What it is: Movement keeps up, but the crosshair repeatedly lands short.

Why it matters: It points to mouse distance rather than keyboard pacing.

Use here: Freeze the passing keyboard and test cm/360 separately.

Dead dash

What it is: A dash you expected did not complete.

Why it matters: Repeated failures can show that a release or next ON did not occur.

Use here: Treat one dead dash as noise; diagnose only a repeated pattern.

RT A-ready boundary

What it is: A travel-capacity reference showing where the selected RT A downstroke can still fit before bottom-out.

Why it matters: It prevents RT D OFF, reversal, and RT A reactivation from being treated as one event.

Use here: Use it for travel math only; it does not measure your reversal or server timing.

GunZ movement sequence

What it is: A repeatable in-game action such as Flash Step, PPQ, or GDHS. The site uses these as tests; it does not teach the movement itself.

Why it matters: A known sequence lets you test input changes without learning a new move at the same time.

Use here: Choose one familiar sequence and keep it fixed during calibration.

11 / EVIDENCE
Evidence boundary

Documented behavior meets personal testing.

Manufacturer and platform documentation explain the controls and input path. The GunZ order, checkpoints, and results come from personal repeat testing and are not universal presets.

What this method does not claim
